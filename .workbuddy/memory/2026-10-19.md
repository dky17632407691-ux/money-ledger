# 2026-10-19

## 手机端「记一笔」页面显示不全 — 已修复并发布
- 症状：iPhone 打开记一笔弹层，页面整体被放大约 1.3 倍，右侧分类被切、底部账户被键盘挡。
- **根因**：iOS Safari 对 font-size < 16px 的输入框，聚焦时自动放大页面（经典行为）。本项目 body 字号 14px，`.input/.select/.textarea` 未设字号继承 14px → 聚焦必触发。不是布局 bug，chips 本身是 flex-wrap 正常的。
- 修复（commit 62df58c，已推 GitHub 并发布）：
  1. `styles.css`：`.input, .select, .textarea` 显式 `font-size: 16px`
  2. `index.html`：viewport 加 `maximum-scale=1`（iOS 手动缩放仍可用，但阻止聚焦自动缩放）
- 经验：今后所有网页项目，输入控件字号一律 ≥16px，否则 iPhone 上必现聚焦放大。

## 手机端溢出的真正根因（iOS zoom 只是次因）
- 用户反馈"还是太大了，没有改变"→ 深挖发现**主因是布局缺陷**：`.form-grid { display:grid }` 未声明 `grid-template-columns`，默认 auto 列取子项最大内容宽度；金额输入框（font-size 34px × 默认 size=20 字符）固有宽度 ~448px，把整列撑到 473px，在 390px 视口下右侧溢出 83px。`.form-grid--2` 原本已用 `minmax(0,1fr)`，基础 `.form-grid` 漏了。
- 修复：`.form-grid { grid-template-columns: minmax(0, 1fr) }`（commit 28a7c97）。CDP 复测：所有层宽 350，overflowCount=0。
- **教训：grid 单列也要写 minmax(0,1fr)**，auto 列会被大字号 input 的固有宽度撑破容器。
- 验证方法（关键工具）：`asset-tracker/measure_viewport.mjs`——CDP Emulation.setDeviceMetricsOverride 精确模拟任意视口（chrome --window-size 在 Windows headless 下会被钳到 512，不可靠），逐层输出宽度链 + 溢出元素清单 + 截图。以后手机端布局问题都用它，不要猜。
- 疑似缓存问题：线上 styles.css 无 Cache-Control 头，Safari 可能一直用旧样式。已在 index.html 给 CSS 引用加 `?v=20261019b` 版本号。以后每次改 CSS/JS 都应递增版本号。

## 发布产生新应用与新域名（重要架构事实）
- 用户确认发布后，本机 deploy 返回**新域名** `https://2111995074905313280.app.workbuddy.host/`（sandboxId e2ee0af39dd442678453d90afc4f10d6），而非旧的 `life-ledger-62150.app.workbuddy.host`。
- 原因：**发布归属跟着 directory + 本机记录走，不跟 appId 走**。旧应用是另一台电脑发布的，本机无归属记录 → 系统新建了应用 B。
- 已验证：新域名云服务完全可用（probe 读 access_allowlist 返回 200、`[{"label":"我"}]`），云服务绑定 publishableKey 而非域名，Origin 不受影响。旧域名仍在线跑旧代码，连同一数据库。
- 决策：以后固定用新域名，只在本机发布；另一台只推 Git 不发布，避免域名再漂移。
- **部署是覆盖式上传、不删文件**：本地删除的 `_origin_probe.html` 线上仍在 → 只能用同名无害文件覆盖（已改为跳转首页）。调试文件不要放进发布目录。
- 坑：后台 http.server 跨天会被回收（curl 502 假象），重启即可；`git commit && git push` 串同一条命令时 push 会静默不执行，必须分两步。
