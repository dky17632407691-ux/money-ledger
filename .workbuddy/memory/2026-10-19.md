## 手机端「记一笔」页面显示不全 — 已修复并发布
- 症状：iPhone 打开记一笔弹层，页面整体被放大约 1.3 倍，右侧分类被切、底部账户被键盘挡。
- **根因**：iOS Safari 对 font-size < 16px 的输入框，聚焦时自动放大页面（经典行为）。本项目 body 字号 14px，`.input/.select/.textarea` 未设字号继承 14px → 聚焦必触发。不是布局 bug，chips 本身是 flex-wrap 正常的。
- 修复（commit 62df58c，已推 GitHub 并发布）：
  1. `styles.css`：`.input, .select, .textarea` 显式 `font-size: 16px`
  2. `index.html`：viewport 加 `maximum-scale=1`（iOS 手动缩放仍可用，但阻止聚焦自动缩放）
- 经验：今后所有网页项目，输入控件字号一律 ≥16px，否则 iPhone 上必现聚焦放大。

## 手机端溢出的真正根因（iOS zoom 只是次因）
- 用户反馈"还是太大了，没有改变"→ 深挖发现**主因是布局缺陷**：`.form-grid { display:grid }` 未声明 `grid-template-columns`，默认 auto 列取子项最大内容宽度；金额输入框（font-size 34px × 默认 size=20 字符）固有宽度 ~448px，把整列撑到 473px，在 390px 视口下右侧溢出 83px。`.form-grid--2` 原本已用 `minmax(0,1fr)`，基础 `.form-grid` 漏了。
- 修复：`.form-grid { grid-template-columns: minmax(0, 1fr) }`（commit 28a7c97）。CDP 复测：所有层宽 350，overflowCount=0。
- **教训：grid 单列也要写 minmax(0,1fr)**，auto 列会被大字号 input 的固有宽度撑破容器。
- 验证方法（关键工具）：`asset-tracker/measure_viewport.mjs`——CDP Emulation.setDeviceMetricsOverride 精确模拟任意视口（chrome --window-size 在 Windows headless 下会被钳到 512，不可靠），逐层输出宽度链 + 溢出元素清单 + 截图。以后手机端布局问题都用它，不要猜。

## 密码登录可行性结论：不可行（已实测）
- 用户诉求：开发阶段不想反复收短信验证码。
- SDK 能力盘点（`AUTH_METHODS`）：`signInWithPassword({username,password})` 可用于**登录**，但**没有**给已有账号设密码的接口：
  - `resetPasswordForOld({oldPassword,newPassword})` 需要旧密码（OTP 注册的账号从未有密码）
  - `resetPasswordForEmail` 只支持邮箱，本项目是手机号
  - `signUp` 要求 verificationToken + password，官方注释明确 provider 拒绝 username+password-only
- 实测探针（写在 `_dev/pwd_probe.html`，已删除）：手工调 `/v1/verification/verify` 换 verification_token，再 `signUp` 补密码 → **被服务端拒绝，此路不通**。
- 登录机制事实（读 SDK）：`sendOtp` 返回 `{verificationId, isExistingUser}`；`verifyOtp` 对已存在用户直接用 verification_token 走 `/v1/signin` 登录，不涉及密码；session 存 localStorage，`expiresAt` 提前 90 秒触发 `refreshOnce` 自动续期（滑动窗口，只要持续使用就不会掉）。
- **结论**：短信验证码是该云服务唯一登录方式，无法消除；能优化的是"别重复登录"。
- 重复登录的真正原因：登录态按 origin 隔离，WorkBuddy 内置预览面板每次都是隔离环境 → 开发时看到的一直是干净会话。**解决方式：交互测试固定用系统浏览器打开 `127.0.0.1:8848`，预览面板只看排版。**
- 可做的体验优化（未做）：登录页预填上次手机号（`rememberedPhone()` 已存在但未用于填充）；验证码输满 6 位自动提交。

## 多币种折算已实现并发布（commit 107d6cb / 6a2f9f1）
- 需求：港美股被当人民币直接相加，持仓盈亏全错。案例：腾讯 200×417.80 HKD 应为 ¥71,134，旧算法算 ¥83,560；苹果 50×343.46 USD 应为 ¥114,770，旧算法算 ¥17,173。

- 实现（不改数据库表，币种由 market 推导）：
  - `quotes.js`：`currencyOf(market)`（hk→HKD、us→USD、其余 CNY）、`CURRENCY_LABEL/SYMBOL`、`fetchFxRates()`
  - `state.js`：`state.fx` + localStorage 持久化（`ledger.fx.v1`，接口挂了用上次值兜底）、`fxRate/holdingCurrency/holdingFxMissing/fxSummary`；折算下沉到 `holdingMarketValue / holdingCost / holdingDayProfit / holdingDayBase / accountTradeCash / realizedSummary`，上层汇总自动正确
  - `views.js`：持仓行显示 `现价 HK$417.80 / 成本 HK$385`，右侧市值为人民币；资产页显示汇率行 + 净值曲线口径提示
  - `sheets.js`：买卖弹层与交易明细按成交币种显示符号，已实现盈亏折人民币；「需要资金」同时给出原币与约合人民币
- 口径决策：成本同样按**当前汇率**折算 → 盈亏只反映股价涨跌，不含汇兑损益；历史快照未折算，切换日曲线有台阶（已在资产页注明）。
- 验证：`_dev/multicurrency_test.html`（临时页，已删）用固定汇率 6.6832/0.8513 逐只核对，四条全 ✓，组合汇总与逐只相加一致，旧算法合计 ¥273,727 vs 新 ¥358,899，差 ¥85,172。
